This map shows how the NFL decision-intelligence proof of concept moves from raw data to structured evidence, deterministic scoring, and Gemini-assisted explanation without allowing the model to control the score.

1. Product Flow

01 INPUTUser selects an NFL matchup and types the exact play.
02 PARSEGemini interprets natural language into a strict play schema. Local parser is the fallback.
03 VALIDATETeam, opponent, player, stat, direction, and line are checked against the selected matchup and demo dataset.
04 FEATURESThe app chooses only evidence relevant to that market: production, usage, matchup, role, injuries, pace, strength, and more.
05 SCOREDeterministic code weights evidence and calculates Signal Strength, Data Confidence, and Final Confidence.
06 EXPLAINGemini receives the already-calculated evidence and turns it into a concise Why Now and Decision Brief.
07 DISPLAYThe user sees supporting evidence, contradicting evidence, missing inputs, risk, and the model used.

3. The Scoring Logic

weightedEvidence = direction × strength × relevance × recency netSignal = Σ(weightedEvidence) / Σ(relevance × recency for present inputs) Signal Strength = |netSignal| × 100 Data Confidence = weighted present inputs / weighted expected inputs × 100 Final Confidence = harmonic mean(Signal Strength, Data Confidence)

Important: a missing input is not scored as zero. It is marked absent, excluded from the directional signal, and lowers Data Confidence.

5. Failure Handling You Built

Ambiguous Input

“Mahomes over 300” does not silently become passing yards. Gemini asks for the missing stat.

Model Overload

A 503 from Gemini 3.8 no longer breaks the flow. MATCHUP retries and moves through the fallback chain.

AI Offline

Supported structured plays can still use the local deterministic parser and deterministic decision brief.

Stale Sports Feed

The ticker polls every 30 seconds, disables cache, and locks verified finals so completed games cannot regress to LIVE.

Missing Evidence

Unknown values stay unknown. They reduce Data Confidence rather than creating false neutral evidence.

Secret Management

.env.local stays outside Git. The status endpoint only reports configuration and connectivity, never the API key.

7. Learning Recap

RAW DATA → NORMALIZED DATA → DERIVED SIGNALS → DETERMINISTIC SCORE → AI EXPLANATION

Data handling

You learned why normalization matters, why null is different from zero, and why confidence should reflect missing evidence.

AI logic

You separated probabilistic language understanding from deterministic business logic. That is the key architectural pattern to reuse.

Resilience

You saw two real-world failures: stale sports data and an overloaded AI model. The product now has explicit fallback behavior for both.

Debugging

You used HTTP status codes, environment diagnostics, Git, build output, API routes, and model fallbacks to isolate failures instead of changing random code.

8. Practice To Reuse

Add one new prop market without touching Gemini's scoring authority

  1. Add the new stat to PropStat in lib/types.ts.
  2. Add the relevant raw player/team field to the controlled dataset.
  3. Teach featureSelector.ts which evidence matters for that stat.
  4. Let score.ts use the same generic evidence weighting.
  5. Expand Gemini's parsing schema to recognize the new stat.
  6. Test one complete play, one contradictory-evidence play, and one ambiguous play.

The key test: the new market should still work deterministically even if Gemini is unavailable.
